### (1) vs. `ux-governance-audit-2026-09-21.md` — "AI Agent 아이덴티티 강화 거버닝 프로세스"

- 기존 항목의 표현: "AI Agent 아이덴티티 강화를 위한 **거버닝 프로세스를 고도화**했다."
- 이번 항목의 표현: "AI Agent **전사 가이드 정립** 및 **제품별 적용**을 통한 경쟁력 확보."
- **에이전트 추정(잠정 결론): 서로 다른 산출물일 가능성이 높다.** 근거:
  - 동사/산출물 종류가 다르다 — 하나는 "거버닝 **프로세스**"(관리·심사 체계, 사후 검증에 가까운
    운영 절차로 추정), 다른 하나는 "**가이드**"(UX/GUI 가이드 1.0이라는 구체적 문서·배포물)이다.
    일반적으로 "거버닝 프로세스"는 산출물의 준수 여부를 지속적으로 심사·관리하는 운영 체계이고,
    "가이드"는 디자이너/기획자가 참조하는 제작 기준 문서로, 성격이 다른 산출물인 경우가 많다.
  - 이번 항목에만 "글로벌 경쟁사 벤치마킹 → 기회 영역 발굴 → 신규 경험 아이디에이션 → 가이드
    배포 → 제품별 적용 협의 → 인터랙션 개선"이라는 구체적 실행 단계가 있는데, 이는 신규 가이드를
    "만드는" 활동에 가깝고, `ux-governance-audit`이 말한 "거버닝 프로세스 고도화"는 기존 체계를
    "운영/개선"하는 활동으로 읽힌다.
  - **가능한 관계**: 이번 항목("가이드")이 먼저 만들어진 신규 제작물이고, `ux-governance-audit`의
    "거버닝 프로세스"는 그 가이드의 준수 여부를 이후 심사·관리하는 상위 운영 체계일 수 있다(가이드가
    "무엇을 만들 것인가"의 기준이라면, 거버닝 프로세스는 "잘 만들어지고 있는가"를 검증하는 절차).
    다만 이는 명칭상 개연성에 근거한 추정일 뿐이며, **두 프로젝트가 같은 팀/이니셔티브 소속인지,
    시기상 선후 관계인지는 사용자 확인이 필요하다.**

### (2) vs. `ax-workflow-p2d-figma-plugin-2026-09-21.md` — "미래 준비 디자인(winning design) 선제안" 프로그램

- 이번 항목도 P2D 플러그인 항목과 **동일하게** "미래 준비 디자인(winning design) 선제안" 과제라는
  문구로 시작한다. P2D 항목의 "진행 단계 분류" 절은 이 상위 과제 아래 "AX 기반 워크플로우 개선 →
  통합 디자인시스템 기반 자동화 → P2D 플러그인 제작 → PoC 개발 중"이라는 구조를 정리한 바 있다.
- **에이전트 추정(잠정 결론): 같은 "미래 준비 디자인(winning design) 선제안" 상위 프로그램 산하의
  별개 세부 과제(sibling task)로 보인다 — 동일 과제를 다르게 서술한 것이 아니라, 같은 프로그램 안의
  또 다른 실행 트랙일 가능성이 높다.** 근거:
  - P2D 항목은 "**UX 경쟁력 강화**"라는 표현을 명시적으로 쓰지 않고 "**AX(워크플로우 효율화) 측면**"
    (UX 조직 스스로의 생산성/자동화)에 초점을 맞춘 반면, 이번 항목은 사용자가 명시한 것처럼
    "**UX 경쟁력 강화 측면**"(제품에 실제로 드러나는 사용자 경험 품질/기능)에 초점을 맞춘다 — 즉 같은
    상위 과제 산하에서 "①조직 워크플로우 자동화(P2D)"와 "②제품 자체의 AI Agent UX 품질(이번 항목)"
    이라는 서로 다른 측면(axis)을 다루는 것으로 읽힌다.
  - 산출물 종류도 다르다 — P2D는 "Figma 플러그인"(디자인 제작 **도구**), 이번 항목은
    "UX/GUI 가이드 1.0"(디자인 제작 **기준 문서**) + 제품 적용/인터랙션 개선이다.
  - 다만 **"미래 준비 디자인(winning design) 선제안"이라는 용어 자체가 정확히 무엇을 가리키는
    고유 프로그램명인지, 아니면 여러 과제에 공통으로 붙는 일반적 상위 목적 표현인지는 여전히
    확인되지 않았다** (P2D 항목의 Open questions에서도 동일하게 미확인으로 남아 있음). 만약 이것이
    특정 연간 과제 프로그램의 공식 명칭이라면, 이번 항목과 P2D 항목은 그 프로그램의 두 개 세부
    과제(sub-initiative)로 나란히 집계해야 하고, 만약 일반 표현이라면 단순히 같은 문구를 재사용한
    서로 무관한 두 프로젝트일 수도 있다. **사용자 확인 필요.**

### (3) vs. `ai-voice-persona-2026-09-21.md` — "AI Agent" 아이덴티티/경험 작업

- AI Voice 항목: "에이전트 보이스 페르소나 가이드라인 수립" + "AI Voice 모델 5종 개발" — **청각
  (voice/음성) 모달리티**의 에이전트 아이덴티티 작업.
- 이번 항목: "AI Agent 전사 가이드 정립"(UX/GUI 가이드 1.0) + "제품별 적용" + "주요 인터랙션 개선" —
  표현상 "GUI"라는 단어가 명시되어 있어 **시각/인터랙션(화면 UI, 상호작용 흐름) 모달리티**에 가깝다.
- **에이전트 추정(잠정 결론): 서로 다른 모달리티를 다루는 별개 산출물일 가능성이 높다 — 다만 같은
  "AI Agent 아이덴티티/경험" 상위 우산 아래 있는 자매(sibling) 과제일 수 있다.** 근거:
  - 이번 항목의 산출물명이 명시적으로 "**UX/GUI** 가이드"라고 되어 있어, AI Voice 항목의 "보이스
    페르소나 가이드라인"과는 다루는 감각 채널이 다르다(시각 vs. 청각).
  - `ux-design-system-webos-micro-2026-09-21.md`(시각/디자인시스템)와 `ai-voice-persona`(청각/보이스)가
    "본부 주력 제품 디자인/디자인 아이덴티티"라는 동일 상위 프로그램 문구를 공유해 사용자가 같은
    프로그램으로 묶어 확인해 준 선례가 있다 — 이는 LG전자 UX연구소가 유사한 방식으로 모달리티별
    가이드를 병행 추진하는 조직 패턴이 있음을 시사한다. 다만 이번 항목은 "본부 주력 제품
    디자인/디자인 아이덴티티"가 아니라 "미래 준비 디자인(winning design) 선제안 / UX 경쟁력 강화"라는
    **다른 상위 프로그램 문구**로 시작하므로, AI Voice·webOS 디자인시스템 프로그램과 이번 항목이
    같은 우산 프로그램인지는 확실하지 않다.
  - **가능성 A**: 이번 "AI Agent 전사 가이드(UX/GUI)"와 "AI Voice 페르소나 가이드라인(청각)"은 함께
    "AI Agent 전체 아이덴티티/경험 가이드"를 구성하는 두 개의 모달리티별 하위 문서일 수 있다(예:
    하나의 "AI Agent 가이드" 아래 GUI 챕터와 Voice 챕터로 나뉘어 있을 가능성).
  - **가능성 B**: 완전히 별도의 두 프로그램("미래 준비 디자인 선제안" vs. "본부 주력 제품 디자인")
    산하에서, 각자 독립적으로 AI Agent 관련 가이드를 만든 별개 과제일 수 있다.
  - **사용자 확인 필요** — 상위 프로그램이 같은지, 두 가이드가 하나의 문서 체계로 통합되어 있는지,
    아니면 독립적으로 관리되는지.

**세 가지 질문 모두 공통적으로 "사용자가 직접 같다/다르다를 확인해 주기 전까지는 별개 항목으로
잠정 기록"하는 것이 안전하다고 판단해, 이번 항목은 독립 파일로 신규 작성했다.**

## Key findings

- **LG전자 UX연구소는 "미래 준비 디자인(winning design) 선제안" 과제에서, "UX 경쟁력 강화" 측면으로
  "AI Agent 전사 가이드 정립 및 제품별 적용을 통한 경쟁력 확보"를 진행했다.** (source: 사용자 제공
  (내부 정보), 2026-09-21)
- **글로벌 경쟁사 벤치마킹을 통해 AI Agent 기회 영역을 발굴했다.** (source: 사용자 제공(내부 정보),
  2026-09-21)
- **신규 경험 아이디에이션을 진행했다.** (source: 사용자 제공(내부 정보), 2026-09-21)
- **이를 기반으로 UX/GUI 가이드 1.0을 배포했다.** — 이 단계는 완료형으로 서술됨. (source: 사용자
  제공(내부 정보), 2026-09-21)
- **제품별 적용 협의를 진행했다.** — 이 단계는 사용자 표현상 "진행"으로, 완료가 아니라 협의가
  이루어지는 중/이루어진 것으로 읽힌다(아래 "진행 상태 분류" 참조). (source: 사용자 제공(내부 정보),
  2026-09-21)
- **주요 인터랙션 개선을 추진했다.** — 이 단계 역시 사용자 표현상 "추진"으로, 완료 확정형이 아니다
  (아래 "진행 상태 분류" 참조). (source: 사용자 제공(내부 정보), 2026-09-21)

## 진행 상태 분류 — 단계별로 완료도가 다르다 (뭉뚱그리지 말 것)

사용자가 제공한 원문 표현을 보면 이 프로젝트의 다섯 단계는 완료도가 균일하지 않다. `09`
(P2D 플러그인) 항목에서 "완료/제안/PoC 개발 중"의 3분류를 도입했던 것과 같은 원칙으로, 이번
항목도 단계별로 나누어 기록한다.

| 단계 | 사용자 원문 표현 | 완료도 해석 |
|---|---|---|
| ① 경쟁사 벤치마킹 → AI Agent 기회 영역 발굴 | "발굴" | 완료형으로 읽힘 |
| ② 신규 경험 아이디에이션 | "진행" | 활동이 이루어졌다는 의미로, 완료형에 가까움(다만 아이디에이션은 본질적으로 산출물이 "확정"이 아니라 "안" 수준일 수 있음) |
| ③ UX/GUI 가이드 1.0 배포 | "**배포**" | **가장 명확한 완료형** — 버전 넘버(1.0)까지 붙어 있어 실제 문서가 나와 배포된 것으로 보임 |
| ④ 제품별 적용 협의 | "**협의를 진행**" | **미완료/진행 중** — "적용 협의"이지 "적용 완료"가 아님. 어떤 제품에 실제로 반영됐는지는 별도 확인 필요 |
| ⑤ 주요 인터랙션 개선 | "**개선을 추진**" | **미완료/진행 중** — "추진"은 착수·진행 단계를 가리키는 표현으로, 개선이 실제 제품에 반영 완료됐다고 단정할 수 없음 |

**결론(에이전트 판단, 근거는 사용자 제공 원문): 이 프로젝트는 "가이드 제작"까지는 완료됐으나,
"가이드의 제품 반영(적용)"은 아직 협의/추진 단계로, 가이드 배포와 실제 제품 적용 사이에 시차가
있는 것으로 보인다.** `report-writer`/`verifier`는 "AI Agent 가이드를 만들었다"와 "AI Agent
가이드가 제품에 반영됐다"를 같은 완료도로 서술하지 말 것.

  소프트웨어가 사용자를 대신해 행동을 취하는 인터페이스를 설계하는 실천으로, 전통적 UI가 다루지
  않던 투명성(에이전트가 무엇을 하고 있는지 보여주기), 상태 전달, 오버라이드(사용자 개입) 제어,
  오류 복구 같은 패턴이 필요하다고 소개된다. Gartner는 2026년 말까지 전체 엔터프라이즈 애플리케이션의
  40%가 특정 업무용 AI 에이전트를 통합할 것으로 전망했으며(2025년 5% 미만 대비 급증), 이는 기존에
  없던 "인터페이스 레이어"가 새로 필요해짐을 의미한다고 보도된다. Microsoft, Salesforce, IBM, AWS,
  Google, Cohere, Glean, Lyzr 등이 각자 엔터프라이즈 AI 에이전트 플랫폼을 출시했다는 보도도 있다.
  NN/g의 "State of UX 2026" 보고서는 신뢰(trust)가 AI 경험 설계의 핵심 과제라고 짚으며, 사용자가
  섣부른 AI 기능에 데인 경험이 있으면 신규 AI 기능 채택에 저항한다고 설명한다 — "점진적 위임
  (progressive delegation)"으로, 사용자의 승인 이력에 따라 자율성 범위를 단계적으로 넓히는 접근이
  이 문제에 대응하는 방식으로 소개된다. 다만 이는 업계 일반 동향 소개이며, LG전자의 "AI Agent
  전사 가이드 1.0"이 이런 투명성·오버라이드·점진적 위임 같은 요소를 구체적으로 포함하는지는 확인된
  사실이 아니다.
  (source: [Agent UX: UI Design for AI Agents in 2026 — Fuselab Creative](https://fuselabcreative.com/ui-design-for-ai-agents/),
  [Understanding Enterprise AI Agents: The 2026 Guide — Lyzr](https://www.lyzr.ai/blog/enterprise-ai/),
  [Enterprise AI Agents: The 2026 Strategy, Selection, and Deployment Guide — Neontri](https://neontri.com/blog/enterprise-ai-agents/))

### 내부(조직·R&D)
- 이번 활동은 "미래 준비 디자인(winning design) 선제안(상위 과제) → UX 경쟁력 강화(관점/측면) →
  AI Agent 전사 가이드 정립 및 제품별 적용(전략) → [경쟁사 벤치마킹 → 아이디에이션 → 가이드 1.0
  배포 → 제품별 적용 협의 → 인터랙션 개선](5단계 실행)"이라는 구조로 이해된다(사용자 제공 정보에
  근거한 해석).
- **(에이전트 자체 추론, 사실 아님) `research/reports/2027-ux-agenda-2026-09-21.md`의 01번 테마
  "에이전틱 UX 신뢰 인프라 완성 — 실패해도 신뢰받는 에이전트로"와 직접 연결되는 실행 증거일 수 있다.**
  해당 테마 본문은 "LG는 AI Voice 5종·거버넌스까지 갖췄지만 아직 베타 단계이고, '실패·정정 UX'가
  가이드라인에 포함됐는지도 미확인"이라고 짚었는데, 이번 항목의 "AI Agent 전사 가이드 1.0"이 바로
  그 테마가 요구한 "전사 차원의 에이전트 UX 가이드"에 해당할 가능성이 있다. 즉 이 리포트가 쓰여진
  시점(2026-09-21) 기준으로 이미 착수되어 있던(가이드 배포까지는 완료된) 작업일 수 있다는 정황
  증거로 읽을 수 있다. 다만:
  - 이 연결은 어디까지나 명칭·주제의 개연성에 근거한 에이전트 추론이며, 두 문서가 실제로 같은
    이니셔티브를 가리키는지 사용자가 확인해 준 사실은 아니다.
  - 테마 01이 지적한 "실패·정정 UX가 가이드라인에 포함됐는지 미확인"이라는 갭이, 이번 "UX/GUI
    가이드 1.0"으로 해소됐는지는 이번 사용자 제공 정보만으로는 알 수 없다(가이드 1.0의 구체
    목차/내용이 제공되지 않았기 때문).
  - 오히려 이번 항목은 위 (1)~(3) 질문에서 보듯 `ux-governance-audit`(거버닝 프로세스)·
    `ai-voice-persona`(보이스 가이드라인)와도 겹칠 가능성이 있어, 테마 01이 언급한 "거버넌스"와
    "AI Voice" 요소들이 사실은 이번 항목과 부분적으로 같은 이니셔티브의 다른 조각일 수도 있다 —
    즉 2027 종합 시 이 네 건(거버넌스, AI Voice, 이번 항목, 및 그 관계)을 하나의 "AI Agent
    아이덴티티/신뢰 인프라" 상위 그림으로 다시 그려볼 필요가 있어 보인다(에이전트 관찰).

## Open questions / gaps

**[최우선] 기존 3건과의 관계 — 위 "최우선 확인 사항" 절의 세 질문**
1. `ux-governance-audit`의 "AI Agent 아이덴티티 거버닝 프로세스 고도화"와 이번 "AI Agent 전사
   가이드 1.0"이 같은 이니셔티브의 다른 단계(가이드 제작 vs. 준수 심사)인지, 완전히 별개 트랙인지.
2. `ax-workflow-p2d-figma-plugin`이 연 것과 동일한 "미래 준비 디자인(winning design) 선제안" 문구가
   이번 항목에도 그대로 쓰였는데, 이것이 같은 연간 프로그램의 공식 명칭으로서 두 항목이 그 프로그램의
   서로 다른 세부 과제(하나는 AX 워크플로우 자동화, 하나는 제품 AI Agent UX)인지, 아니면 우연히 같은
   표현을 재사용한 무관한 두 과제인지.
3. `ai-voice-persona`의 "에이전트 보이스 페르소나 가이드라인"(청각)과 이번 "AI Agent 전사 가이드"
   (UX/GUI, 시각)이 하나의 "AI Agent 가이드" 문서 체계 안의 모달리티별 챕터인지, 별도로 관리되는
   독립 문서인지.

**[그 외 세부 공백]**
- **"글로벌 경쟁사 벤치마킹"의 대상** — 구체적으로 어떤 경쟁사(삼성, Google, Amazon, Apple, 중국
  브랜드 등)를 벤치마킹했는지 명시되지 않았다.
- **"AI Agent 기회 영역"의 구체 내용** — 벤치마킹을 통해 어떤 갭/기회가 발굴됐는지(예: 실패 처리,
  멀티턴 대화, 권한 위임 UX 등) 구체적으로 제공되지 않았다.
- **"UX/GUI 가이드 1.0"의 실제 목차/범위** — 어떤 원칙·컴포넌트·인터랙션 패턴을 다루는지, 위에서
  언급한 업계 표준 요소(투명성, 오버라이드, 실패·정정 UX 등)가 포함되는지 확인되지 않았다.
- **"제품별 적용 협의"의 대상 제품과 현재 상태** — 어떤 제품 라인(가전, TV, 모바일 액세서리 등)과
  협의 중인지, 협의가 초기 단계인지 합의 임박 단계인지 불명확.
- **"주요 인터랙션 개선"의 구체 내용** — 어떤 인터랙션이, 어떤 방식으로 개선됐는지(또는 개선 예정
  인지) 구체적 항목이 제공되지 않았다.
- **시기** — 2026년 중 정확히 언제(상반기/하반기, 특정 분기) 각 단계가 진행/완료됐는지 명시되지
  않았다. 특히 가이드 1.0 배포 시점과 제품 적용 협의 시작 시점 간의 시차도 불명확.
- **"1.0"이라는 버전 표기의 함의** — 향후 2.0 등 개정 계획이 있는지(즉 지속적으로 갱신되는 리빙
  다큐먼트로 운영되는지) 확인되지 않았다.
- 외부에 공개된 정보가 아니므로, 2027 사업계획 외부 공유 자료에 이 내용을 포함할 경우 사내 보안/
  공개 범위 정책을 먼저 확인해야 한다.
