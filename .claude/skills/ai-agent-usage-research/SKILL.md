# AI 에이전트 실사용 동향 리서치 스킬

이 스킬은 `competitor-research` → `verifier` → `interview` → `report-writer` 4단계 상시 에이전트
파이프라인을 "AI 전문가들의 실제 에이전트 사용 방식" 조사에 맞게 스코핑하는 브리프 템플릿이다.
제품 스펙이나 마케팅 발표가 아니라 **"실무에서 실제로 어떻게 쓰는지"**(워크플로우·패턴·도구 조합)에
초점을 둔다.

> [가져온 스킬] 원래 `3개 경쟁사 조사 서브 에이전트` 세션(브랜치 `claude/funny-tesla-40dplh`)에서
> `competitor-researcher → research-verifier → report-writer` 3단계 파이프라인용으로 작성됐던 것을,
> 이 저장소의 상시 에이전트 이름(`competitor-research`/`verifier`/`interview`/`report-writer`)에
> 맞춰 갱신한 버전이다. 조사 범위·원칙 등 본문 내용은 원본과 동일하다.

## 언제 쓰는가

- LG전자의 AI 에이전트 전략(내부 개발 프로세스, 또는 제품에 넣을 에이전트 UX)을 위해
  업계 최전선 사용 패턴을 참고하고 싶을 때
- "AI 에이전트가 실제로 어디에 쓰이는지"를 제품 발표가 아니라 실사용 사례/증언 기반으로 알고 싶을 때

## 조사 범위 (기본 템플릿)

### 트랙 1 — 실무자·전문가의 실사용 패턴
대상 예: 소프트웨어 개발(에이전틱 코딩 — Claude Code, Cursor, Devin류), 리서치/분석, 마케팅/콘텐츠,
고객지원, 데이터/운영 자동화 등 직군별로 나눠 조사. 조사 항목:
- 어떤 도구/에이전트를 쓰는지 (제품명 구체적으로)
- 단일 에이전트 vs 멀티 에이전트(orchestrator-subagent, 병렬 실행 등) 패턴
- 자율성 수준 — 완전 자동 실행 vs "제안만 하고 사람이 승인" 같은 human-in-the-loop 설계
- 실제 생산성/품질에 대한 (가능하면 정량적) 증언·데이터, 실패 사례/한계에 대한 언급도 함께 수집

### 트랙 2 — 지역/커뮤니티별 특징
- 미국(실리콘밸리 스타트업·빅테크) vs 해외(유럽/아시아) 등 지역별 채택 속도·용도 차이가 있으면 기록
- 컨퍼런스 발표, 개발자 블로그, X/트위터·해커뉴스·레딧 등에서 확인되는 실무자 담론
  (단, SNS 기반 정보는 반드시 "커뮤니티 의견/일화(anecdotal)"로 구분 표기 — 공식 통계로 취급하지 않음)

### 트랙 3 — 에이전트 프레임워크·인프라 동향
- MCP(Model Context Protocol) 같은 도구 연동 표준, 멀티 에이전트 오케스트레이션 프레임워크,
  에이전트 평가(eval)/안전장치 관행 등 "어떻게 만들고 운영하는지"의 실무 패턴

## 파이프라인 실행 방법

1. **브리프 작성**: 위 템플릿에 실제 조사하고 싶은 직군/지역/도구 범위를 채워 브리프를 만든다.
2. **`competitor-research` 에이전트**에 브리프를 전달해 리서치 실행 (출처 URL 필수, 일화성 정보는
   출처와 함께 "anecdotal"로 명시하도록 별도 지시). 결과는 `research/findings/`에 저장된다.
3. **`verifier` 에이전트**로 각 claim 교차검증 — 특히 정량적 수치(예: "생산성 N% 향상")는
   과장 여부를 반드시 재확인한다 (`research/verification/`에 저장).
4. **`interview` 에이전트**로 사용자와 함께 빈틈·추가 조사 필요 항목을 짚고, 후속 조치를
   `research/interview/`에 남긴다 — 필요하면 2~3단계를 반복한다.
5. **`report-writer` 에이전트**로 최종 보고서 작성 — 직군별/지역별 섹션 + "LG전자가 참고할 수 있는
   실무 패턴" 시사점 섹션을 포함할 것을 권장한다 (`research/reports/`에 저장).

## 원칙

- 제품 마케팅 문구와 실제 사용자 증언을 명확히 구분한다 (마케팅 자료 인용 시 출처에 "(공식 발표)"
  라고 표기).
- 정량적 생산성 수치는 출처의 방법론(누가, 몇 명, 어떻게 측정)이 확인되지 않으면 "검증 필요"로
  표시하고 액면 그대로 인용하지 않는다.
- 이 스킬은 조사 스코프 정의용이다 — 실제 웹 리서치·검증·인터뷰·보고서 작성은 항상 4단계 상시
  에이전트 파이프라인(`competitor-research` → `verifier` → `interview` → `report-writer`)에 위임한다.
