# UX 조직 내부 역량 강화 리서치 스킬

이 스킬은 `competitor-research` / `own-company-research` → `verifier` → `interview` → `report-writer`
파이프라인을 **"사업 경쟁력"이 아니라 "UX 조직 자체의 역량 강화"** 관점으로 스코핑하는 브리프
템플릿이다. 두 관점은 다른 질문이다:

- **사업 경쟁력** (`ai-ux-trend-research`가 다루는 영역): 우리 제품/서비스가 시장에서 경쟁사 대비
  어떤 UX·AI 기능을 갖춰야 하는가.
- **내부 역량 강화** (이 스킬이 다루는 영역): 우리 UX·디자인·리서치 조직 사람들이 AI를 활용해서
  **어떻게 더 빠르고 정확하게, 더 적은 반복 작업으로 일할 수 있는가.**

같은 원자료(사례·인터뷰)라도 이 두 렌즈로 각각 다른 인사이트가 나온다 — 예를 들어 "AI로 앱 리뷰를
분석해 이탈 신호를 찾는 도구"라는 하나의 사례에서, 사업 경쟁력 관점으로는 "경쟁사가 이런 기능을
제품에 넣고 있다"가 나오지만, 내부 역량 강화 관점으로는 "우리 UX 리서처가 사용자 피드백을 수동으로
태깅하는 대신 이런 방식으로 자동화할 수 있다"가 나온다. **둘 다 뽑아내는 것이 이 스킬의 핵심이다.**

## 조사 범위 (기본 템플릿)

### 트랙 1 — UX 리서치 업무의 AI 활용
- 사용자 인터뷰/피드백/리뷰 데이터를 AI로 분석·태깅·패턴 추출하는 사례 (예: 리뷰 마이닝으로 이탈
  신호 찾기 — 리서처가 수동으로 하던 어피니티 매핑·코딩 작업의 대체/보조)
  이런 실사용 사례를 발견하면, 리서치 업무가 아닌 다른 직군(세일즈, 마케팅 등) 사례라도
  "리서처 워크플로우에 그대로 옮겨올 수 있는가"를 판단해 기록한다.
- 인터뷰 대상자 소싱/스크리닝 자동화
- 정성 데이터(인터뷰 녹취, 오픈서베이 응답)를 명시지(문서화된 인사이트)로 전환하는 패턴

### 트랙 2 — 디자인/프로토타이핑 워크플로우의 AI 활용
- AI 기반 빠른 프로토타이핑, 디자인 시스템 자동화, 디자인-개발 핸드오프 효율화 사례
- 인터랙티브 산출물(정적 PDF/덱 대신 살아있는 프로토타입·데모)로 전환한 사례

### 트랙 3 — 조직 지식 관리·온보딩
- 사내 지식을 "사람이 아니라 에이전트가 읽도록" 설계한 위키/SSOT 구조 (예: 에이전트가 작업 전
  항상 참조하는 문서 체계)
- 신규 인력 온보딩, 암묵지의 명시지化(생각을 구조화해주는 스킬/플러그인 활용)
- CLAUDE.md류 지침으로 에이전트가 모르는 것을 되묻게 만드는 패턴

### 트랙 4 — 조직 전체 AI 도입 확산 전략
- 교육 커리큘럼, 인센티브 설계(잘 쓰는 사람이 보상받는 구조), 실패 요인(자동화 도구로만 오인,
  개인 스킬과 공용 스킬 제작 난이도 차이 등)
- 도입 후 안착까지 걸린 기간, 조직 내 확산 방식(자발적 전파 vs 하향식 강제)

## 출처 범위에 대한 원칙

**경쟁사(가전/스마트홈)에 한정하지 않는다.** UX 조직의 내부 역량 강화 사례는 업종을 가리지 않고
참고가 된다 — 세일즈 조직, 마케팅 조직, B2B SaaS 회사 등 어디서 나온 사례든 "UX 워크플로우에
적용 가능한가"를 기준으로 채택한다. 다만 findings 파일에는 반드시 원 사례의 업종/직군을 명시해서,
report-writer가 "직접 적용 가능"과 "유추 적용 필요"를 구분할 수 있게 한다.

## 파이프라인 실행 방법

1. **브리프 작성**: 조사하고 싶은 UX 업무 영역(리서치/디자인/지식관리/조직확산 중 어디)과, 참고할
   업종 범위(가전 UX 한정 vs 업종 무관)를 정해 브리프를 만든다.
2. **`competitor-research` 또는 `own-company-research` 에이전트**에 브리프를 전달한다. 결과를
   `research/findings/competitor/` 또는 `research/findings/own-company/`에 저장하되, 아래 이중
   구조를 findings 파일 안에 명시적으로 포함하도록 지시한다:

   ```
   ## 사업적 시사점
   - (제품/시장 경쟁력 관점에서 이 사례가 의미하는 것)

   ## 내부 역량 강화 시사점
   - (우리 UX 조직이 이 사례에서 그대로 가져오거나 응용할 수 있는 것 — 구체적으로 어떤 업무를
     어떻게 바꿀 수 있는지)
   ```

3. **`verifier` 에이전트**로 사실관계를 교차검증한다 — 특히 "역량 강화 효과"를 주장하는 정성적
   서술(예: "생산성이 좋아졌다")은 정량적 근거가 있는지 반드시 확인한다.
4. **`interview` 에이전트**로 사용자와 "이게 실제로 우리 UX 조직에 적용 가능한지, 어떤 제약이
   있는지"를 논의하고 후속 조사 항목을 `research/interview/`에 남긴다.
5. **`report-writer` 에이전트**로 최종 보고서를 작성한다 — 반드시 "사업 경쟁력" 섹션과 "UX 조직
   내부 역량 강화" 섹션을 분리하여, 두 관점 모두에서 실행 가능한 제안을 담도록 한다.

## 원칙

- 사업 경쟁력 인사이트만 뽑고 내부 역량 강화 인사이트를 누락하지 않는다 — 이 스킬을 쓰는 이유
  자체가 후자를 놓치지 않기 위함이다.
- "우리도 이렇게 하면 좋겠다"는 제안은 항상 원 사례의 구체적 실행 방식(도구, 프로세스, 조직
  설계)까지 함께 기록한다 — 막연한 트렌드 서술("AI로 효율화하고 있다")로 끝내지 않는다.
- 업종이 다른 사례를 가져올 때는 반드시 원 업종/직군을 명시하고, UX 업무로 옮길 때 생기는 차이점
  (데이터 종류, 워크플로우 단계 차이 등)을 함께 서술한다.
